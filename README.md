## Зачем нужен WDTTSL

Обычный VPN чаще всего решает задачу «весь трафик через туннель». WDTTSL построен вокруг другой идеи: **обычное подключение остаётся основным, а VPN используется выборочно**.

Это особенно полезно, когда нужно:

- на **Android** отправлять в туннель только выбранные приложения;
- на **Windows** направлять в VPN только нужные IP, подсети, сайты или готовые списки маршрутов;
- не менять обычный маршрут для всего компьютера;
- управлять клиентом и Linux-сервером из одного проекта;
- использовать один и тот же Rust-транспорт на разных клиентских платформах.

## Что выделяет WDTTSL

Это не просто ещё один GUI для VPN. В одном проекте объединены возможности, которые обычно приходится собирать из нескольких отдельных инструментов.

| Возможность | Android | Windows |
|---|:---:|:---:|
| VPN через Rust-клиент CSQTT / VPNSL | ✅ | ✅ |
| Выбор установленных приложений | ✅ | — |
| Режим «только выбранные» / «исключить выбранные» | ✅ | — |
| Селективные IPv4/CIDR-маршруты | — | ✅ |
| Импорт `.bat`, `.txt`, `.list` | — | ✅ |
| Профили **«Через VPNSL» / «Напрямую»** | — | ✅ |
| Генератор маршрутов по доменному имени | — | ✅ |
| Пакетное применение сотен маршрутов | — | ✅ |
| Нативный Wintun-интерфейс | — | ✅ |
| Установка Linux-сервера по SSH из GUI | — | ✅ |
| Серверные бинарники `amd64`, `arm64`, `armv7` | ✅ | ✅ |
| Тёмный интерфейс | ✅ | ✅ |

### Ключевая идея проекта

> **Android выбирает приложения. Windows выбирает адреса и сети. Сервер и транспорт остаются общей основой.**

Именно такое сочетание делает WDTTSL удобным не только как VPN-клиент, но и как инструмент управляемой маршрутизации.

<p align="center"><i>Маршрутизация по адресам/файлам и параметры клиента VPNSL для Windows.</i></p>

Windows-клиент использует единый тёмный интерфейс, Wintun и селективную таблицу маршрутов. По умолчанию компьютер продолжает работать через обычное активное подключение — Wi‑Fi, Ethernet или другое соединение. В VPNSL уходят только те направления, которые включены в профилях.

### Маршруты без ручного `route add`

Поддерживаются:

- одиночные IPv4, например `203.0.113.10/32`;
- CIDR-подсети, например `203.0.113.0/24`;
- готовые файлы `.bat`, `.txt`, `.list`;
- включение/отключение профиля одним переключателем;
- выбор направления **Через VPNSL** или **Напрямую**;
- пакетное добавление больших списков маршрутов;
- изменение профилей без полного перезапуска VPN;
- экспорт текущего набора маршрутов обратно в BAT.

### Маршруты по сайтам

Во вкладке маршрутизации можно указать доменное имя, получить его актуальные IPv4-адреса и сформировать BAT-профиль. Это удобно для сервисов, которые нужно отправлять в туннель отдельно от остального интернета.

> [!NOTE]
> Домены и CDN могут менять IP-адреса. Сгенерированный список отражает адреса на момент разрешения имени и иногда требует обновления.

### Wintun + обычная сеть одновременно

Windows-клиент создаёт виртуальный интерфейс через **Wintun**, но не делает его обязательным default route для всего компьютера. В результате можно одновременно использовать:

- обычный интернет — для большей части трафика;
- VPNSL — только для выбранных сетей.

### Сервер из того же приложения

Во вкладке **«Установка»** Windows-клиента можно подключиться к VPS по SSH и установить/переустановить сервер. В пакет включены Linux-бинарники для:

- `amd64`;
- `arm64`;
- `armv7`.

То есть базовое развёртывание сервера можно выполнить без ручного поиска и загрузки отдельного бинарника.

## Android

Ветка `main` содержит Android-клиент на базе оригинального CSQTT и Android `VPNService`.

### Маршрутизация по приложениям

Android-клиент поддерживает два сценария:

1. **только выбранные приложения через VPN**;
2. **выбранные приложения мимо VPN**.

Это позволяет маршрутизировать по самому приложению, когда заранее неизвестно, к каким адресам и CDN оно будет подключаться.

### Дополнительные возможности Android

- список установленных приложений с поиском;
- поддержка системных приложений;
- Quick Settings Tile;
- виджет управления;
- Android TV-интерфейс;
- отдельные политики поведения для мобильной сети и Wi‑Fi;
- работа с тем же серверным Rust-ядром.

## Почему это не обычный full-tunnel VPN

Типичная схема VPN:

```text
Компьютер/телефон → VPN → весь интернет
```

WDTTSL:

```text
                         ┌─ обычный интернет
Приложение / Windows ────┤
                         └─ VPNSL → только выбранные направления
```

Это уменьшает количество лишнего трафика через VPS и позволяет не ломать локальные сервисы, банковские приложения, стриминг или другие ресурсы, которым VPN не нужен.

## Архитектура

```text
┌─────────────────────────┐             ┌──────────────────────────┐
│ Android                 │             │ Windows                  │
│ VPNService              │             │ WPF + Wintun             │
│ выбор приложений        │             │ IPv4/CIDR + route files  │
└────────────┬────────────┘             └────────────┬─────────────┘
             │                                       │
             └──────────────┬────────────────────────┘
                            ▼
                   ┌────────────────┐
                   │ Rust client    │
                   │ CSQTT / VPNSL  │
                   └───────┬────────┘
                           │ TURN / RTP transport
                           ▼
                   ┌────────────────┐
                   │ Linux server   │
                   │ Rust           │
                   └───────┬────────┘
                           ▼
                        Internet
```

Клиентские интерфейсы адаптированы под платформу, но транспортная и серверная логика имеют общую Rust-основу.

## Windows 1.0.0

Актуальный публичный релиз: **[VPNSL Windows v1.0.0](https://github.com/Nakortanax/WDTTSL/releases/tag/v1.0.0)**.

### Быстрый старт

1. Скачайте **[Setup.exe](https://github.com/Nakortanax/WDTTSL/releases/download/v1.0.0/VPNSL-1.0.0-Windows-x64-Setup.exe)** или **[Portable ZIP](https://github.com/Nakortanax/WDTTSL/releases/download/v1.0.0/VPNSL-1.0.0-Windows-x64.zip)**.
2. Portable-архив распакуйте полностью и запускайте `VPNSL.Windows.exe`.
3. Подтвердите UAC — права администратора необходимы для Wintun и таблицы маршрутизации.
4. Во вкладке **«Туннель»** задайте Peer, пароль и параметры подключения.
5. Во вкладке **«Маршруты»** добавьте CIDR вручную или загрузите файл маршрутов.
6. Выберите **«Через VPNSL»** или **«Напрямую»**.
7. Нажмите **«Подключить»**.

## Практические сценарии

### Только ChatGPT / конкретный сервис через VPN

Загрузите или создайте список IP/CIDR сервиса, выберите **«Через VPNSL»** — остальной Windows-трафик продолжит идти напрямую.

### Приложение на Android использует неизвестные адреса

Выберите само приложение в Android-клиенте. Маршрутизация работает на уровне приложения, поэтому не требуется заранее знать весь список его серверов.

### Большой готовый список сетей

Импортируйте `.bat`, `.txt` или `.list`. Windows-клиент применяет маршруты пакетно, а не запускает отдельный процесс для каждой записи.

### Новый VPS

Откройте вкладку **«Установка»**, укажите SSH-доступ и разверните подходящий серверный бинарник для архитектуры VPS.

## Ограничения

- Windows-релиз предназначен для **Windows 10/11 x64**.
- Windows-маршрутизация в текущей реализации ориентирована на **IPv4/CIDR**.
- Выбор приложений есть на Android и намеренно отсутствует в Windows-клиенте.
- Для Wintun и изменения таблицы маршрутизации нужны права администратора.
- IP-адреса сайтов/CDN могут меняться, поэтому доменные профили иногда нужно обновлять.
- Проект не является коммерческим VPN-сервисом: сервер пользователь разворачивает самостоятельно.
