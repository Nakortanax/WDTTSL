## Что такое WDTTSL

WDTTSL объединяет в одном проекте Android-клиент, Windows-клиент и Linux-сервер VPNSL/CSQTT. Главная идея — **селективная маршрутизация**: обычный интернет остаётся основным подключением, а через защищённый туннель идут только выбранные направления.

Это удобно, когда VPN нужен не для всего устройства, а для конкретных приложений, сайтов, IP-сетей или наборов маршрутов.

### Что отличает этот fork

| Возможность | Android | Windows |
|---|:---:|:---:|
| VPN через существующий Rust-протокол CSQTT/VPNSL | ✅ | ✅ |
| Выбор установленных приложений | ✅ | — |
| Режим «включить выбранные» / «исключить выбранные» приложения | ✅ | — |
| Селективные маршруты IPv4/CIDR | — | ✅ |
| Импорт списков `.bat`, `.txt`, `.list` | — | ✅ |
| Направление профиля **«Через VPNSL» / «Напрямую»** | — | ✅ |
| Генератор маршрутов по доменному имени | — | ✅ |
| Нативный туннель Windows через **Wintun** | — | ✅ |
| Установка/переустановка Linux-сервера по SSH из интерфейса | — | ✅ |
| Серверные бинарники `amd64`, `arm64`, `armv7` | ✅ | ✅ |
| Тёмный интерфейс | ✅ | ✅ |

> **Редкое сочетание проекта:** Android-маршрутизация по приложениям + Windows-маршрутизация по адресам и файлам + управление Linux-сервером, при этом транспортный Rust-клиент и сервер остаются общей основой.

## Windows 1.0.0

Актуальный публичный Windows-релиз: **[v1.0.0](https://github.com/Nakortanax/WDTTSL/releases/tag/v1.0.0)**.

### Селективная маршрутизация

По умолчанию Windows продолжает использовать обычное физическое подключение — Ethernet, Wi‑Fi или другое активное соединение. В VPNSL направляются только включённые правила.

Поддерживаются:

- одиночные IPv4-адреса, например `203.0.113.10/32`;
- IPv4-подсети/CIDR, например `203.0.113.0/24`;
- импорт существующих файлов маршрутов `.bat`, `.txt`, `.list`;
- профили с направлением **Через VPNSL** или **Напрямую**;
- включение/отключение профилей без ручного редактирования таблицы маршрутизации;
- пакетное применение больших списков маршрутов;
- разрешение домена в IPv4 и создание BAT-файла маршрутов;
- журнал работы клиента, Wintun и маршрутизатора.

### Wintun вместо системного «полного VPN»

Windows-клиент создаёт виртуальный интерфейс через **Wintun**, принимает конфигурацию туннеля от Rust-клиента и добавляет только необходимые маршруты. Благодаря этому основная таблица маршрутизации Windows остаётся обычной, а выбранные сети получают отдельный путь через VPNSL.

### Установка сервера из Windows

Во вкладке **«Установка»** можно подключиться к VPS по SSH и установить или переустановить серверную часть. В Windows-пакет входят серверные компоненты для Linux:

- `x86_64 / amd64`;
- `arm64`;
- `armv7`.

Это позволяет развернуть клиент и сервер из одного набора без ручного поиска подходящего бинарника.

> [!NOTE]
> В Windows-версии **нет маршрутизации по отдельным приложениям**. Эта функция реализована в Android. Windows использует маршруты IPv4/CIDR и профили файлов — такое разделение сделано намеренно.

## Android

Основная ветка `main` содержит Android-клиент на базе оригинального CSQTT. В нём используется Android `VPNService`, а выбор приложений встроен непосредственно в интерфейс.

### Маршрутизация приложений

Android-клиент умеет работать в двух режимах:

- **исключать выбранные приложения** из туннеля;
- **направлять в туннель только выбранные приложения**.

Список формируется из установленных приложений, поддерживает поиск, системные приложения и быстрое изменение набора с перезагрузкой VPN-политики.

### Дополнительные возможности Android

- Quick Settings Tile для быстрого управления VPN;
- виджет приложения;
- Android TV-интерфейс и отдельные TV-политики;
- автоматическая политика при Wi‑Fi в Android-версии;
- профили DNS и серверные настройки;
- универсальные и архитектурные Android-сборки.

## Быстрый старт — Windows

1. Скачайте **[Setup.exe](https://github.com/Nakortanax/WDTTSL/releases/download/v1.0.0/VPNSL-1.0.0-Windows-x64-Setup.exe)** или **[Portable ZIP](https://github.com/Nakortanax/WDTTSL/releases/download/v1.0.0/VPNSL-1.0.0-Windows-x64.zip)**.
2. Для portable распакуйте архив полностью и запускайте `VPNSL.Windows.exe`.
3. Разрешите запрос UAC — права администратора нужны для Wintun и таблицы маршрутизации Windows.
4. Во вкладке **«Туннель»** укажите Peer, пароль и остальные параметры подключения.
5. Во вкладке **«Маршруты»** добавьте CIDR вручную или загрузите файл маршрутов.
6. Выберите направление профиля **«Через VPNSL»** или **«Напрямую»**.
7. Нажмите **«Подключить»**.

## Сервер

Серверная часть написана на Rust и предназначена для Linux. Репозиторий содержит скрипты развёртывания и поддержку нескольких архитектур. В зависимости от сценария сервер может работать как системный сервис или разворачиваться через Docker.

Windows-клиент дополнительно предоставляет графический сценарий установки по SSH, чтобы базовое развёртывание не требовало ручной загрузки бинарников на VPS.

## Для кого проект

WDTTSL особенно полезен, если нужно:

- оставить большую часть трафика на обычном соединении;
- направить в VPN только выбранные Android-приложения;
- на Windows отправлять в VPN только конкретные сайты/IP-сети;
- работать с готовыми списками маршрутов вместо ручного `route add`;
- иметь Android, Windows и серверную часть в одном проекте;
- самостоятельно развернуть сервер на своём Linux VPS.

---

## Ограничения

- Windows-релиз сейчас предназначен для **Windows x64**.
- Windows-маршрутизация работает с **IPv4/CIDR**; доменный генератор преобразует домен в актуальные IPv4-адреса на момент генерации.
- Изменение IP-адресов CDN/сайта может потребовать обновления списка маршрутов.
- Для Wintun и изменения маршрутов Windows требуются административные права.
- Выбор приложений доступен на Android, но не реализован в Windows-клиенте.
