# CSQTT 2.5.0 — изолированная серверная ветка для VPNSL

**Статус: исходники импортированы, интеграция и совместимость НЕ подтверждены. Не устанавливать поверх действующего VPNSL.**

Источник: [amurcanov/csqtt](https://github.com/amurcanov/csqtt), тег [v2.5.0](https://github.com/amurcanov/csqtt/releases/tag/v2.5.0), commit `fd936ef087c34cc46f26111dc2361f43b8b03c07`, релиз от 20.10.2026. Репозиторий upstream архивирован. Файлы `rust-server/`, `shared/` и `deploy.sh` импортированы побайтово без изменений; исходные Git blob SHA записаны в `UPSTREAM_BLOBS.tsv`. Исходная лицензия PolyForm Noncommercial и обязательные уведомления приведены в корневом `LICENSE` VPNSL, который совпадает с upstream.

**Лицензирование:** у upstream 2.5.0 файл `rust-server/Cargo.toml` содержит поле `license = "Unlicense"`, но его корневой `LICENSE` и уведомления указывают **PolyForm Noncommercial 1.0.0**. Это противоречие не разрешено; при переносе сохранены исходный код и некоммерческие уведомления, а изменение лицензии не предполагается.

## Почему импорт изолирован

Существующие выпуски VPNSL Android 1.0.10 и Windows 1.0.3 основаны на серверной линии CSQTT 2.1.9 с собственными доработками (потоки, кадры, восстановление, установка и маршрутизация). Сборка Android 1.0.10 намеренно пакует проверенный серверный бинарник из Windows 1.0.2. Нельзя заменить его исходниками 2.5.0 без перепроверки протокола и логики установки.

**Идентификатор `CSQTT-WIRE-3` недостаточен для доказательства совместимости!** Версия 2.5.0 тоже печатает эту строку, но пакетные форматы/семантика различаются:

- В VPNSL 2.1.9 `GETCONF` идентифицирует устройство и имеет другую раскладку полей; в 2.5.0 сервер использует пароль и другую раскладку, хотя имеет fallback для старой формы.
- VPNSL 2.1.9 передаёт `TUNCONF:...:stream-v2`, upstream 2.5.0 — `TUNCONF:...:stream-v1`.
- Новая версия использует общий код `shared/dtls.rs`, другой фрейминг и обработку SRTP/DTLS. Ранее VPNSL использовал `flow_frame.rs`, `striped_scheduler.rs` и `selective_fec.rs`.
- В оригинальном `deploy.sh` версии 2.5.0 есть операции остановки и удаления предыдущих systemd/Docker runtime и освобождения UDP-портов. **Не выполнять его на работающем VPS.**

## Структура и сборка (без развёртывания)

```
server-updates/csqtt-2.5.0/
├── rust-server/       — исходники Rust сервера 2.5.0
├── shared/            — исходный общий код 2.5.0 (в том числе DTLS)
├── deploy.sh          — upstream установщик, только для анализа и лабораторного теста
├── UPSTREAM_BLOBS.tsv — контрольные Git SHA файлов
└── check-source.sh    — проверки и локальная сборка без запуска сервиса
```

Проверить точное соответствие upstream и компилируемость в изолированном Linux окружении:

```bash
bash server-updates/csqtt-2.5.0/check-source.sh
```

Требуется `git`, `bash`, `cargo` и Rust 1.97.1, доступ к crates.io либо уже заполненный Cargo cache. Скрипт сверяет Git blob SHA, синтаксис установщика, запускает `cargo test --locked` и `cargo build --release --locked`, проверяет `--protocol-revision` и **не** выполняет установку.

## Что нужно для использования нового сервера

1. Отдельный лабораторный VPS/контейнер, отдельный UDP-порт, резервная копия конфигурации и базы SQLite; production-сервис не трогать.
2. Зафиксировать тестовую матрицу Android 1.0.10, Windows 1.0.3 и обновлённого клиента 2.5.0. Проверить GETCONF/TUNCONF, разные режимы RTP/SRTP, TURN, DNS и переподключение.
3. При несовместимости обновить клиентские Rust-ядра и Android/Windows интеграцию **отдельным** PR или ввести явное согласование версии протокола. Не пытаться отключить проверку `WIRE-3` ради установки.
4. Только после успешных E2E-тестов собрать три Linux бинарника amd64/arm64/armv7 на существующих сборщиках Forgejo, проверить ELF, архитектуру, происхождение и перенастроить упаковку APK/Windows. Это отдельный этап.
5. Перед production-переходом сделать резервную копию БД и иметь проверенную возможность возврата на работающую версию. Не включать автообновление.

Оригинальные версии Android/Windows, существующий `rust-server/`, корневой `shared/` и действующий установщик `app/src/main/assets/deploy.sh` при этом импорте **не меняются**.
